# Complete product implementation sequence

Every milestone belongs to one required final product. External activation does not remove functionality from this scope. The detailed feature inventory and acceptance status are maintained in IMPLEMENTATION_CHECKLIST.md; measured results and limits are recorded in VERIFICATION.md.

| Milestone                                             | Required deliverable                                                                                                                                                                                                                                                                                         | Verification boundary                                                                                                                               |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Business and architecture                          | Inspect the existing offer, official logo and repository; preserve £5,000 discovery, £15,000 fixed implementation and the alternative 25% agreed outcome model; define seven-step delivery, tenant roles, data entities and provider boundaries.                                                             | Source/content review; no invented credentials, case studies or binding terms.                                                                      |
| 2. Premium public experience                          | All public service, method, security, pricing, verification, contact, FAQ, legal/configuration and system pages; shared brand, responsive navigation, purposeful engineering/financial diagrams, SEO and accessibility.                                                                                      | Route, keyboard, contrast, responsive and visual checks.                                                                                            |
| 3. Persistence and identity                           | SQL migrations, organisations, membership/invitations, verified accounts, sessions, recovery, account settings, mandatory staff MFA, server permissions and audit history.                                                                                                                                   | Real PostgreSQL and HTTP authentication; direct tenant/role attacks and recovery tests.                                                             |
| 4. Commerce                                           | Server-priced orders, scope/legal/tax snapshots, Stripe Checkout/signatures, idempotent events/fulfilment, cancellations, refunds/disputes/reconciliation, confirmations and safe engagement claiming.                                                                                                       | Local adapter explicitly test-only; offline official-SDK contracts; real provider sandbox acceptance separately required.                           |
| 5. Onboarding and evidence                            | Resumable reviews, least-privilege AWS role templates/external IDs, real STS/billing/inventory collectors, scoped evidence, private local/S3 files, quarantine and ClamAV.                                                                                                                                   | Negative access/pagination contracts, persisted submissions, file isolation and actual scanner checks. Live AWS/S3 checks need authorised accounts. |
| 6. Customer and fulfilment workspaces                 | Dashboard, engagements, ledger/search/filter/export/detail, remediation, exact-revision approval, customer deployment/rollback evidence, deliverables, support, billing, proposals and company/team settings. Administrative customer, order, enquiry, engagement, record, review and operations interfaces. | Complete authenticated browser journeys and persisted state checks; illustrative views remain read-only and isolated.                               |
| 7. Financial verification and implementation payments | Traceable baseline, observation, normalisation and annualisation with review/publication; changed sources invalidate signoff. Fixed implementation payable only after agreement. Outcome fee requires accepted fee basis, published evidence and a separately approved payment request.                      | Financial edge cases, revisions, role authority, duplicate billing prevention and end-to-end approved outcome checkout.                             |
| 8. Operations and release                             | Durable jobs, SMTP outbox, retries/dead letters, monitoring hooks, health, security headers, CI, reproducible Docker web/worker, AWS Terraform reference, backup/restore and activation runbooks.                                                                                                            | Type/lint/test/build/audit, worker/container smoke checks, isolated restore, Terraform validation and explicit provider/deployment limits.          |

Core persistent entities include accounts/sessions/MFA, organisations/members/invitations, engagements, versioned onboarding/opportunity/remediation/approval/deployment/deliverable/verification/proposal/support/update records, audit/revision history, orders/payment events/legal snapshots, AWS connections/checks/billing snapshots, private files, enquiries/replies, durable jobs, settings and transactional mail.

The final external activation step collects approved commercial/legal/tax material, provider accounts, authorised AWS test roles, production storage/email/monitoring configuration and hosting access. No development task is deferred merely because those secrets are unavailable. Activation never substitutes a simulation for a real production integration, and replacing hkgpipi.com requires explicit deployment authorisation.
